# 《驿 · 十二夜》游戏设计文档（GDD）

> 版本 1.0 · 2026-11-23
> 类型：回合制资源调度 / 风险管理
> 平台：Windows 桌面（pygame-ce，单文件 exe）
> 单局时长：15–25 分钟
> 一句话：你是山口驿站的驿丞。十二个夜晚，把北边的战报送过山。

---

## 1. 设计目标

### 1.1 想让人体验到什么

**「我做了取舍，而且我知道我为什么做这个取舍。」**

不是「我赢了」，是「我在只剩两个骑手、一匹马、暴雪要来的情况下，选择送那份八百里加急，放掉了另外三封——然后我赌对了」。

### 1.2 目标玩家

- 玩《欧陆风云》《冰汽时代》《Papers, Please》这类**系统性压力管理**游戏的人
- 喜欢**读数字、算余量、做计划**，不喜欢手速和运气主导
- 能接受失败，且失败后想知道「哪一步错了」

### 1.3 不做什么（明确排除）

| 不做 | 原因 |
|---|---|
| 实时操作 | 目标玩家要的是思考时间，不是反应时间 |
| 战斗系统 | 战争只作为信的背景存在，玩家看不到战场 |
| 随机爆死 | 所有损失都必须可归因到某个决定或某条已知概率 |
| 长剧情 | 叙事通过「信件原文」渗透，不做过场 |
| 数值通胀 | 十二夜固定长度，不给无限滚雪球的机会 |

## 2. 核心循环

```
┌─────────────────────────────────────────────────┐
│  黄昏 · 收信                                     │
│  3~5 封战报到达，各自有：目的地、期限、赏、罚     │
└───────────────────┬─────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  排班 · 决定                                     │
│  给每封信指派骑手（或拒收）                       │
│  可以花油点灯、可以让骑手歇一晚                   │
└───────────────────┬─────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  夜 · 模拟                                       │
│  天气兑现 → 行进 → 事件 → 抵达/延误/失联          │
└───────────────────┬─────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  黎明 · 结算                                     │
│  送达得金 + 得信；延误/失联扣信                   │
│  骑手回来（或者没回来）                           │
└───────────────────┬─────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│  整备 · 消费                                     │
│  买马、雇人、修路、买油                           │
└───────────────────┬─────────────────────────────┘
                    ↓
              下一夜（共 12 夜）
```

## 3. 系统设计

### 3.1 三类资源

| 资源 | 说明 | 耗尽会怎样 |
|---|---|---|
| **信**（0–100） | 朝廷对你的信任 | 归零 → 立即失败（驿被撤） |
| **金** | 结算收入 | 归零不失败，但买不起东西 |
| **油** | 点灯用 | 归零 → 夜间行进速度 -35% |

**信是唯一的失败线。** 金和油都是手段。

### 3.2 骑手

| 属性 | 范围 | 作用 |
|---|---|---|
| 脚力 `speed` | 1.0 – 1.6 | 决定行进速度 |
| 体力 `stamina` | 0 – 100 | 低于 30 时速度 -25%；跑一趟扣 25–40 |
| 状态 `state` | 待命 / 在外 / 受伤 | 受伤要歇 1–2 夜 |

**体力恢复**：歇一晚 +35。所以「轮换」是核心操作。

**雇人**：花金，属性随机（略高于初始）。

### 3.3 马

| 属性 | 范围 | 作用 |
|---|---|---|
| 脚力 `speed` | 1.0 – 1.5 | 与骑手脚力相乘 |
| 状态 `condition` | 0 – 100 | 低于 40 时速度 -20%；跑一趟扣 15–30 |

**马不会自己恢复**，要花金「喂料」恢复，或者买新马。

**这是设计上的一个硬约束**：马是消耗品，逼玩家做长期预算。

### 3.4 路线

| 路线 | 距离 | 特点 |
|---|---|---|
| **北口** | 3 | 雪天极慢，晴天最快 |
| **河渡** | 4 | 雨天涨水，慢 |
| **旧矿道** | 5 | 稳定，不受天气影响，但总是慢 |

**行进时间** = `距离 ÷ (骑手脚力 × 马脚力 × 天气系数 × 灯系数)`

结果向上取整到「夜」。**≤ 期限 = 送达。**

### 3.5 天气

五种：晴 / 阴 / 雨 / 雪 / 暴雪

| 天气 | 北口 | 河渡 | 旧矿道 | 事件风险 |
|---|---|---|---|---|
| 晴 | 1.0 | 1.0 | 1.0 | 低 |
| 阴 | 0.95 | 1.0 | 1.0 | 低 |
| 雨 | 0.85 | 0.6 | 1.0 | 中 |
| 雪 | 0.5 | 0.85 | 1.0 | 中 |
| 暴雪 | 0.3 | 0.7 | 1.0 | 高 |

**天气预报**：黄昏时给出「今夜预报」，**准确率 70%**。

> 这是整个游戏的信息核心。玩家永远在「按预报排班」和「按保守排班」之间选。
> 预报说晴，但三成可能是雪——你要不要押？

### 3.6 事件

夜里按路线风险掷骰：

| 事件 | 概率 | 效果 |
|---|---|---|
| 顺风 | 8% | 提前一夜 |
| 迷路 | 10% | 延后一夜 |
| 落石 | 6%（北口雪天 ×2） | 原路返回，信未送出 |
| 遇劫 | 5%（暴雪 ×2） | 信件丢失，扣重罚 |
| 无事 | 其余 | — |

**所有事件都有明确概率，且受天气调制。** 玩家可以算。

### 3.7 信件

每封信：

| 字段 | 说明 |
|---|---|
| 目的地 | 三条路线之一 |
| 期限 | 1 或 2 夜（夜数，不是绝对日期） |
| 赏 | 送达得金 |
| 罚 | 延误/丢失扣信 |
| 原文 | 一两句战报，纯氛围 |

**信分为三等**：

- **寻常**：赏少罚少，期限宽
- **加急**：赏高，期限 1 夜，罚重
- **八百里**：赏极高，期限 1 夜，罚极重，且占用最强骑手

**拒收不罚。** 这是关键设计——玩家永远可以「少接一封」。

### 3.8 升级

| 项目 | 价格 | 效果 |
|---|---|---|
| 雇骑手 | 120 | 新增一名随机属性骑手 |
| 买马 | 150 | 新增一匹随机属性马 |
| 喂料 | 40 | 一匹马状态 +40 |
| 加油 | 30 | 油 +40 |
| 修路 | 200 | 指定路线距离 -1（每条只能修一次） |

**价格是固定的，不随购买次数上涨**——避免「越买越贵」的挫败感，但金的总量有限，自然形成选择。

### 3.9 胜负

- **12 夜结束**：信 ≥ 60 → 通关；信 < 60 → 也算活下来了，但结局文本不同
- **信归零**：立即失败
- **评价**：按最终信 + 送达率给 S/A/B/C

## 4. 数值平衡

### 4.1 开局

```
信 = 50
金 = 200
油 = 100
骑手 ×2：脚力 1.15 / 1.25，体力 100
马 ×2：脚力 1.10 / 1.20，状态 100
```

### 4.2 目标曲线

| 夜 | 期望信 | 期望金 |
|---|---|---|
| 1 | 52 | 150 |
| 4 | 58 | 400 |
| 8 | 65 | 700 |
| 12 | 70+ | 1000+ |

**前 3 夜是教学期**：天气温和，信件宽裕。
**第 6 夜起压力上升**：暴雪概率提高，八百里出现。
**第 10–12 夜**：连续恶劣天气，逼玩家用掉所有积蓄。

### 4.3 难度调节

单一难度，但**种子可复现**（`--seed`），方便玩家复盘。

## 5. 表现设计

### 5.1 视觉

**程序化绘制，无外部美术资源。**

- 主色调：夜蓝 `#0e1620` / 灯火橙 `#e8a04c` / 雪白 `#dfe8ee`
- 驿站剪影：三角屋顶 + 窗格暖光
- 山口：三层远近山脊，用噪声生成，可复现
- 粒子：雪、灯火余烬
- 界面：木牌质感（深色底 + 描边 + 细高光）

**所有图形由代码生成**，这样：
1. exe 不含外部资源，体积小
2. 每局地形微变，但不影响玩法
3. 没有版权问题

### 5.2 字体

系统中文字体：优先 `Microsoft YaHei`，回退 `SimHei` → `SimSun`。
若都缺失，回退 pygame 默认字体（会缺中文，需在 README 注明）。

### 5.3 音效

**用 numpy 合成，输出 WAV，运行时载入。**

| 音效 | 合成方式 |
|---|---|
| 鸟鸣/风 | 低通白噪声 + 缓慢包络 |
| 马蹄 | 短噪声脉冲 + 低频正弦 |
| 铃 | 正弦 + 快速衰减 + 泛音 |
| 送达 | 三音上行（五声音阶） |
| 失败 | 两音下行 |
| 落雪 | 极低音量高频噪声，循环 |

音乐：一段缓慢的 drone（两个相差五度的正弦 + 缓慢 LFO），可循环。

### 5.4 反馈

- 送达：金色粒子 + 铃
- 延误：界面轻微抖动 + 短促低音
- 失败：屏幕渐暗 + 风雪声

## 6. 技术方案

### 6.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.14 | 机器上已有 |
| 图形 | pygame-ce 2.5.8 | 已装，SDL2 稳定 |
| 数值 | numpy | 已装 |
| 音频 | numpy 合成 → WAV | 无需外部资源 |
| 打包 | PyInstaller | 已装，可出单文件 exe |

### 6.2 目录结构

```
relay/
  main.py                 入口
  relay/
    __init__.py
    version.py
    core/
      __init__.py
      balance.py          所有可调数值集中于此
      models.py           Rider / Horse / Dispatch / Route / Weather
      events.py           夜间事件表
      sim.py              GameState：夜幕推进、结算
      report.py           结算报告与结局判定
    ui/
      __init__.py
      theme.py            颜色 / 字体 / 尺寸
      widgets.py          按钮、卡片、进度条
      art.py              程序化绘制（山、屋、雪）
      fx.py               粒子系统
      scenes.py           标题 / 主界面 / 结算
      app.py              主循环与状态机
    audio/
      __init__.py
      synth.py            WAV 合成
      player.py           载入与播放
  tools/
    gen_audio.py          离线生成音效
    sim_balance.py        批量模拟胜负率
  tests/
    test_models.py
    test_sim.py
    test_balance.py
  docs/
    GDD.md
    README.md
    CHANGELOG.md
```

### 6.3 关键约定

- **核心逻辑与渲染完全分离**：`core/` 不 import pygame，可无头测试
- **所有随机走统一 RNG**：`GameState` 持有一个 `random.Random(seed)`
- **所有数值在 `balance.py`**：改数值不改逻辑
- **模拟是纯函数式的**：`advance_night(state, plan) -> NightResult`，不改全局

### 6.4 性能

目标：1280×720 @ 60fps，集显可跑。
雪粒子上限 400，超出复用。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 排班做得太简单（最优解唯一） | 让天气不确定、骑手属性有差异，制造多解 |
| 挫败感过强（一次失误就崩） | 信的下限给缓冲；拒收不罚 |
| 中文字体在 exe 里丢 | 打包时探测系统字体路径，缺失则明确报错 |
| pygame 在无 GPU 环境卡 | 限制粒子数，关闭 vertical sync 做降级 |
