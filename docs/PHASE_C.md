## 2. 三个反直觉的发现

### ① 马恢复参数完全不影响吞吐

```
马恢复      每局派遣   送达率   信中位   马低状态
2           10.62     67.4%    49      55.6%
4           10.63     67.9%    52      51.1%
6           10.57     67.8%    50      51.4%
8           10.60     67.9%    52      47.3%
```

**派遣数一点没变。**

原因：低状态的马**仍然可以被派出去**，只是跑得慢。
所以马的状态影响送达率，不影响吞吐。

**我一开始以为「52% 的马低于门槛」是主要瓶颈，判断错了。**

### ② 真正的吞吐瓶颈是「马被占用」，不是马的状态

```
120 局统计：
  理论派遣格（可用骑手/马取小）  3571
  实际派出                      1275
  利用率                        35.7%

「一夜一封都没派」的原因：
  无可用马    227 次   ← 主因
  无可用骑手   31 次
  无可派信件   13 次
```

**`available_horses()` 排除的是**在途**的马，不是低状态的马。**

### ③ 编制失衡：4 个骑手配 2 匹马

```
终局骑手数  中位 4（最多 6）
终局马数    中位 2
终局金      中位 142

买马需要 255 金（155 + 100 余量），终局金只有 142
雇人 130 比买马 155 便宜 → AI 先雇人
```

**人一堆，马两匹，最多同时跑 2 趟。**

**试了「马优先」的 AI：**

```
现状 AI    达标 30.0%  S 5.3%  派遣 10.59  终局马 2.0
马优先 AI  达标 24.7%  S 7.3%  派遣 11.53  终局马 3.0
```

**吞吐 +9%，但达标 −5%。** 因为买马的钱是从喂料和添油里挤出来的。
这不是 bug，是真权衡。

## 3. 策略前沿是断崖式的

```
min_margin=0（接受零余量）   达标 30.0%   S 5.3%
min_margin=1（要求 1 夜余量） 达标 79.3%   S 10.7%
min_margin=2（要求 2 夜余量） 达标  0.0%   ← 根本没有这种信
```

**没有中间地带。** 「接不接这趟风险」不是渐变，是开关。

### 为什么

```
		寻常        加急        八百里
		slack=+1    slack=0     slack=0

北口	期限 2      期限 1      期限 1
河渡	期限 3      期限 2      期限 2
矿道	期限 3      期限 2      期限 2
```

**`ROUTE_BASE_NIGHTS` 是按**最优组合 + 晴天**算的。**

北口基准 1 夜，只有「快组合（1.25×1.20=3.0/夜）在晴天」能做到。
慢组合（老陈 1.15 × 乌蹄 1.10 = 2.53/夜）要走 2 夜。

**所以加急和八百里天生零余量：任何天气变化或事件都必挂。**

而高信值只有加急（4.5）和八百里（6.7）。
**想要 S 就必须零余量，就必须接受高失败率。**

## 4. 参数扫描结果

| 方案 | 达标 | S率 | 信中位 |
|---|---|---|---|
| 现状 | 32.5% | 5.0% | 49 |
| 马恢复 2→4 | 32.5% | 5.0% | 52 |
| 喂料 +40→+60 | 30.0% | 3.3% | 48 |
| 加急松弛 0→1 | 32.5% | 5.0% | 49 |
| **八百里松弛 0→1** | **42.5%** | **10.8%** | **56** |
| 马恢复4 + 喂料60 | 30.8% | 4.2% | 50 |
| 马恢复4 + 加急/八百里 +1 | 42.5% | 10.0% | 56 |
| **全套 + FPD 2.8→3.2** | **55.0%** | **19.2%** | **62** |

**单条最有效的是「八百里松弛 +1」。**

因为它把唯一的高信值来源（6.7 信）从「必挂」变成「能做」。

## 5. 我的判断

**当前 27% 达标不是「玩家学不会」，是数学上够不到。**

```
起点 50，11 趟派遣，送达率 67%，平均 3.1 信
期望终局 = 50 + 11 × 0.67 × 3.1 ≈ 73
S 线 80
```

**即使全部按计划成功，12 趟 × 3.1 = 37 → 87，也只是刚过 S。**

**任何失败都会把 S 推走。**

### 需要调整的三件事（按优先级）

1. **打通吞吐**——现在 35.7% 的利用率太浪费。
   可以把马的价格降下来，或者让 AI 更早买马。
   但要注意：吞吐上去会让失败次数也上去。

2. **给高价值信件一点余量**——八百里 slack 0→1 是单条最有效的。
   但这会削弱「八百里 = 冒险」的定位，需要想清楚。

3. **最后才是 `FAITH_PER_DELIVER`**——它是乘积项，最后调。

### 我不建议现在做的

- **不要**为了提高胜率而削事件。事件现在 31.9% 的触发率是健康的。
- **不要**加专属负面事件来抑制矿道。龙娘明确反对，我也同意。
- **不要**一次改多个参数。现在还没搞清哪个是主因。

## 八策略对比（各 250 局）

```
策略        达标     S率    信中位  每局派遣  送达率
------------------------------------------------------
smart       78.0%   8.4%    67     9.5     80.5%
safe        77.2%  11.2%    67     9.4     80.6%
smart_alt   77.2%   7.6%    67     9.3     80.8%
base        28.8%   4.4%    47    10.5     68.1%
lean        28.0%   4.4%    46    10.9     67.6%
wide        27.6%   4.8%    46    10.4     68.0%
faith       24.0%   3.2%    43    10.2     66.1%
bold        19.2%   1.2%    40    10.0     63.6%
```

## 三个结论

### ① Q1 的两种编制公式，结果完全一样

```
smart      target = min(骑手总数, team_cap)      78.0%
smart_alt  target = min(骑手总数, 马总数)        77.2%
```

**差 0.8 个百分点，在 250 局样本里是噪声。**

所以「用哪个公式算编制目标」这个问题的答案是：**都不重要**。
两种公式都能到 77%。问题从来不在公式上。

### ② 「雇 4 人买 2 马」不是原因，是结果

```
base    派遣 10.5 封   → 需要更多马
safe    派遣  9.4 封   → 2 匹马够了
```

保守打法本身就不派那么多信，所以用不着那么多马。
**编制失衡是保守策略的副产品，不是吞吐瓶颈。**

裁决里那句「不允许仅凭 AI 马少人多就断定是数值问题」——
**数据支持这个判断：那确实不是数值问题。**

### ③ 真正的问题：`safe` 在**达标和 S 上同时最优**

```
safe  达标 77.2%  S 11.2%   ← 两项都第一
bold  达标 19.2%  S  1.2%
```

**冒险在任何维度上都不划算。** 这不是「保守能活、冒险能拿 S」的权衡——
保守连 S 都更好。

那 50 个百分点的差距全部来自一个开关：`min_margin >= 1`
（只接有余量的信，零余量的不接）。

## 对设计的含义

「天气赌局」是这游戏的核心机制，但它现在是**纯亏损**的：
- 赌赢了：多拿 4.5~6.7 信
- 赌输了：信归零或大罚款
- 实测：期望为负，而且负得厉害

**这不是调一个系数能解决的。** 要么让高价值信件的期望转正
（给余量 / 提高奖励 / 降低罚款），要么承认「天气赌局」只是氛围，
核心决策变成「排班效率」。

按裁决，**我不在没拿到 GPT 裁决前改平衡参数**。这一节只是记录数据。
