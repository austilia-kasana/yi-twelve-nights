## 🔴 立刻要做的

### 1. 「行程夜数」是假的（最根本的一条）

**现状**：一封信写着「需要 2 夜」，但骑手**下一夜立刻可用**。

`nights` 只是一个用来和 `deadline` 比大小的数字，
并不真的产生「在途」状态。结果是：

- 1 夜的行程和 3 夜的行程，占用骑手的时间完全一样
- 「路远」这件事**没有任何代价**
- 于是旧矿道（距离 5、天气免疫）在暴雪天变成**既最快又最安全**

**这一条同时解释了三个已经观察到的问题：**

1. 旧矿道在暴雪下等效距离 5.00，而北口 10.00、河渡 5.71 —— 矿道最快
   （哈基米的第 7 条）
2. 「只接有余量的」比「赌预报」S 率高 14 个百分点（57.3% vs 43.3%）
   —— 因为保守不需要付任何人力代价
3. 玩家感觉不到「押上这趟，人就回不来了」的张力

**改法**：给骑手/马加 `in_transit` 状态，行程真实占用 N 夜。

**代价**：`ROUTE_BASE_NIGHTS` 全部重算、500 局平衡重跑、
UI 要加在途显示、可能还要加「召回」机制。**这是一次大改。**

**判断**：这是这个游戏从「像样」变成「真的有意思」的分界线。
现在的核心机制「赌预报」在设计上是假的——因为保守永远不亏。

### 2. 渲染快照测试

**为什么要做**：S-01（界面泄漏真实天气）是单测和模拟器都发现不了的类型。
它只藏在「玩家看到什么」这一层。R-09（预报没有反馈）同理。

**方案**：给 `theme.text()` 加一个全局记录开关，测试时把所有绘制过的字符串
收进 list，然后对 list 做断言。改动小、快、稳。

```python
def test_no_weather_leak():
    gs = GameState(seed=5)
    gs.forecast, gs.weather = "clear", "storm"
    scene = PlayScene(app, gs)
    scene.plan[d.id] = (r.id, h.id)
    with T.recording() as texts:
        scene.draw(surf)
    assert "按预报 2 夜" in texts
    assert "4 夜" not in texts        # 不能出现实际值
```

### 3. 同一夜最多一封八百里

**现状**：每封信独立抽种类，实测第 5 夜出过两封八百里，
其中一封（北口·限 1 夜）在数学上不可能完成。

**为什么算 🔴**：玩家看到做不到的任务会有「被耍了」的感觉，这是信任问题。

## 🟡 应该做的

### 4. 难度选项

现在所有数值硬编码在 `balance.py`。三档建议：
- **驿丞（易）**：S 率 ~60%
- **驿令（标准）**：现状，S 率 ~40%
- **驿使（硬）**：S 率 ~15%，关掉马自然恢复

### 5. 种子输入框

exe 现在无法指定种子（windowed 模式不接受命令行参数）。
日志里记了种子，玩家想复盘却没路走。

### 6. 日志在游戏内可翻页

现在显示最近 7 条。打到第 9 夜还是看不见第 5 夜。

### 7. 骑手 0 体力时的视觉提示

可以派（合理设计），但卡片应该变灰 + 显示「力竭」。现在和满体力看起来一样。

### 8. 存档槽 UI

**现状**：存档功能已可用，但只有一个自动槽在界面上。
`save.py` 里三个手动槽的接口都有了，缺的是「存档/读档」菜单。

## 🟢 锦上添花

### 9. 结局文本变体

现在只有三档通用文案。可以按本局实际情况生成专属回顾：
送达率 ≥ 90% / 八百里 ≥ 2 封全成 / 遇劫 ≥ 2 次 / 最后一夜收手。

### 10. 白天支线

驿站本身的经营：旅人、修屋、存粮。
**这会把 25 分钟的局拉长到 40 分钟，需要重新评估节奏。**

### 11. 真正的配乐

现在只有 numpy 合成的 drone + 风声。

### 12. 自定义剧本

用 JSON 描述信件池、天气表、结局文本。

## 明确不做的

| 想法 | 不做的理由 |
|---|---|
| 实时操作 | 目标玩家要的是思考时间。实时会把「算余量」变成「拼手速」 |
| 战斗系统 | 战争只该作为信的背景存在。画一场战斗不如画一封没送到的信 |
| 无限模式 | 12 夜的固定长度是这个游戏张力的来源 |
| 数值通胀（越买越贵） | 金的总量本来就有限，自然会形成选择。涨价只是增加挫败感 |
