# 后续计划

> 按「我认为的价值」排序，不按工作量。
> 带 🔴 的是我认为**必须先做**的，🟡 是应该做的，🟢 是锦上添花。

---

## 🔴 立刻要做的

### 1. 存档 / 读档

**为什么最重要**：一局 25 分钟，中途有事就得从头再来。这是目前唯一一个
**会真正阻止玩家把游戏玩下去**的问题。

**已有基础**：`GameState.to_dict()` 已经写好，产出的是纯 JSON（含 RNG 状态）。

**要做的**：
- `GameState.from_dict(d)` —— 反序列化，注意 `itertools.count` 的 id 计数器要对齐
- 存档槽（3 个手动槽 + 1 个自动槽）
- 主界面加「继续」按钮
- 存档格式带 `version` 字段，加载时做兼容
- `App.QUIT` 事件里自动存一次（打 `interrupted` 标记）

**风险**：`models.py` 里的 `_id_counter` 是模块级 `itertools.count`，
读档后必须跳到已有最大 id 之后，否则会撞号。这是最容易漏的地方。

---

### 2. 渲染快照测试

**为什么要做**：`ISSUES.md` 里 S-01（界面泄漏真实天气）是单测和模拟器都发现不了的
类型。它只藏在「玩家看到什么」这一层。

**方案**：
```python
# tests/test_render.py
def test_no_weather_leak():
    gs = GameState(seed=5)
    gs.forecast, gs.weather = "clear", "storm"     # 预报晴，实际暴雪
    scene = PlayScene(app, gs)
    scene.plan[d.id] = (r.id, h.id)
    text = extract_texts(scene, ...)               # 或者截图做 OCR
    assert "按预报 2 夜" in text
    assert "4 夜" not in text                      # 不能出现实际值
```

**难点**：pygame 没有「读取已绘制文本」的接口。可行的做法：
- 把 `T.text()` 调用打桩记录（最可靠，但要改 theme）
- 或者截图 + OCR（慢，但不用改代码）

**我倾向第一种**：给 `theme.text()` 加一个全局 `_record` 开关，测试时打开，
把所有绘制过的字符串收进 list，然后对 list 做断言。改动小、快、稳。

### 3. 同一夜最多一封八百里

**现状**：`_make_dispatch()` 每封信独立抽种类。实测第 5 夜出过两封八百里，
其中一封（北口·限 1 夜）在数学上不可能完成。

**改法**：`begin_night()` 生成完 dispatch 列表后检查，超过一封就把多余的降级为加急。

**为什么算 🔴**：玩家看到做不到的任务会有「被耍了」的感觉，这是信任问题。

## 🟡 应该做的

### 4. 难度选项

现在所有数值硬编码在 `balance.py`。做法：把关键几项抽成 `Difficulty` 对象
（`faith_per_deliver` / `horse_recovery` / `penalty_mult` / `dispatches_per_night`）。

三档建议：
- **驿丞（易）**：S 率 ~60%，给第一次玩的人
- **驿令（标准）**：现状，S 率 ~38%
- **驿使（硬）**：S 率 ~15%，关掉马自然恢复

### 5. 种子输入框

exe 现在无法指定种子（windowed 模式不接受命令行参数）。
日志里记了种子，玩家想复盘却没路走。

**最小实现**：标题页加一个输入框，回车开始。或者启动时读 `seed.txt`。

### 6. 日志在游戏内可翻页

现在显示最近 7 条。打到第 9 夜还是看不见第 5 夜。
加「↑ / ↓」翻页，或者一个可滚动的全屏日志面板。

### 7. 骑手 0 体力时的视觉提示

可以派（合理设计），但卡片应该变灰 + 显示「力竭」。现在和满体力看起来一样。

## 🟢 锦上添花

### 8. 结局文本变体

现在只有三档通用文案。可以按本局的实际情况生成一句专属回顾：

- 送达率 ≥ 90%：「这条驿路在你手里没有出过一次岔子。」
- 八百里 ≥ 2 封全成：「北边的人开始叫它『铁驿』。」
- 遇劫 ≥ 2 次：「山里的人都认识你了，不管是好是坏。」
- 最后一夜还没派信就收手：「你知道什么时候该收手。」

### 9. 白天支线

GDD 里提过，一直没做。驿站本身的经营：旅人、修屋、存粮。
**这会把 25 分钟的局拉长到 40 分钟，需要重新评估节奏。**

### 10. 战役模式

十二夜 × 三章。每章继承骑手和马，但信和钱重置。
需要设计「跨局继承什么」。

### 11. 真正的配乐

现在只有 numpy 合成的 drone + 风声。可以：
- 用同样的方法合成一段五声音阶的极简旋律
- 或者在 ComfyUI 之外找免费的 CC0 音乐

### 12. 自定义剧本

用 JSON 描述信件池、天气表、结局文本。让玩家能做自己的「驿站故事」。

## 明确不做的

| 想法 | 不做的理由 |
|---|---|
| 实时操作 | 目标玩家要的是思考时间。实时会把「算余量」变成「拼手速」 |
| 战斗系统 | 战争只该作为信的背景存在。画一场战斗不如画一封没送到的信 |
| 无限模式 | 12 夜的固定长度是这个游戏张力的来源。无限滚雪球会毁掉它 |
| 数值通胀（越买越贵） | 金的总量本来就有限，自然会形成选择。涨价只是增加挫败感 |
