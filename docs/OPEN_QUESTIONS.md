## Q1 · 事件让游戏从 82% 掉到 46%，这个落差合理吗？

**数据（150 局，同种子）：**

```
关掉每夜事件：达标 82.7%   S 44.0%   信中位 75
开启每夜事件：达标 41.3%   S 12.7%   信中位 55
```

**但我核对过概率换算是对的：**

```
实测每夜事故率 5.5%（期望 5.99%）
实测每趟至少一次事故 24%（旧模型理论值 29%）
```

**事故率甚至比旧模型还低，胜率却掉了 41 个百分点。**

### 隔离实验（这一步才看清）

把事件拆成「好事件」和「坏事件」分别打开：

```
事件照抽但完全无效果    达标 72.7%   ← 只是抽了骰子，不产生任何效果
只有顺风有效          达标 74.7%   ← 好事件几乎不改变结果
只有坏事件有效        达标 39.3%   ← 坏事件是主因
全套（现状）          达标 47.3%   ← 好事件只补回 8 点
```

**结论：坏事件代价约 33 个百分点，好事件只补回 8 点。严重不对称。**

### 我现在的解释（需要评审确认）

**旧模型**：`travel_nights` 用**出发夜天气一次算死**。
计划 2 夜 = 保证 2 夜（在没有事件的前提下）。

**新模型**：天气每夜变。
计划 2 夜的信，**即使没有任何事件**，也可能因为中间变天而走成 3 夜。

**所以「余量」在事件介入之前就已经被天气吃掉了一部分。**
坏事件是在一个已经吃紧的行程上再补一刀——它命中率没变，但每次命中造成的失败概率更高了。

**如果这个解释对，那真正的问题不是「事件太重」，而是：**

> **在途模型下，天气每夜变 + 事件每夜抽，两个随机源在同一个「余量」上叠加。**

旧模型只有一个随机源作用于行程（事件）；现在是两个。

### 我想要的判断

1. 这个解释对不对？
2. 如果对，该削哪个——事件，还是「天气每夜变」这个设计？
   （后者是龙娘当初坚持的，我不想擅自推翻）
3. 还是说 46% 达标 / 14% S 本来就该是「有这个系统的游戏应有的难度」，
   只要玩家学会在计划时留出天气余量，就能打回来？
   ——**但 AI 已经在用 `forecast` 估算余量了，它做不到。**

**这条比任何数值都重要。如果是机制理解错了，Phase C 怎么调都是在错误的基础上调。**

## Q2 · `planned_nights` 该用「乐观」还是「期望」？

事件概率换算的分母，我用的是**出发时 `travel_nights()` 的结果**——这是最乐观估计（假设出发夜天气持续）。

实测分布：

```
计划 1 夜：11%
计划 2 夜：84%
计划 3 夜：4%
```

按 `p_night = 1-(1-p)^(1/planned_nights)` 换算，计划 2 夜的每夜概率是 15.8%，
两夜累计 29%——正好等于旧模型的每趟概率。

**但实际行程分布是：**

```
1 夜 18%    2 夜 65%    3 夜 14%    4 夜 2%
```

**实际比计划长。** 所以实际累计事故率会超过 29%。

**我的疑问**：换算基数该用哪个？

- **A. 乐观**（现状）：保证了「计划内的累计概率」正确
- **B. 期望**（按天气加权平均速度算）：保证了「实际的累计概率」正确
- **C. 固定值**（比如 2.0）：最简单，但忽略路线差异

**我倾向 B，但不确定算「期望速度」的复杂度值不值得。**
而且如果按 B，长路线的每夜概率会被摊薄，等于「走远路更安全」——这可能是反的。

## Q3 · 顺风该不该能「省下一整夜」？

**这个我改过一次。**

最初设 `tailwind: progress_mult = 1.5`，结果实测发现**顺风救不了任何一趟**：

```
矿道距离 5，每夜推进 2.5
  正常：    夜1=2.5  夜2=5.0  → 2 夜到
  顺风一夜：夜1=3.75 夜2=6.25 → 还是 2 夜到
```

**因为整数夜是一道坎。** 1.5 倍不够跨过去。

改成 2.0 之后（一夜走两夜的路），顺风确实能省夜了，胜率从 44% → 51%。

**但我担心：「一夜走两夜的路」在叙事上太强了。** 风再大也不该让马跑出两倍。

**有没有第三种做法？** 比如顺风不是加速，而是「减少这条路的总距离」（抄了近道）。
那样和叙事更贴，也不会出现「2 倍速」这种数字。

## Q4 · 落石必须近乎必死吗？

**数据：**

```
rockfall 69 趟，送达率 16%
lost    139 趟，送达率 60%
robbery 100 趟，送达率  0%
```

**落石 84% 的失败率，太狠了。** 它只占 4% 的趟数，但贡献了大量失败。

原因：`progress_mult=0` + `distance_add=1`。对 2 夜行程来说，
这一夜白走 + 路变长 20% = 必然赶不上。

**但我又想不出更好的定义。** 「路塌了只能绕」如果不加距离，那它就是「一次迷路」的马甲。

**选项：**
- 保持现状（几乎必死，但罕见）
- 只 `progress=0`，不加距离（等于「一夜白走」）
- 改成 `progress=0` 且该任务**允许超期一次**（不扣罚，只算送达）

第三个有意思，但引入了新概念。

## Q6 · 矿道还是 44%，这个结构性问题怎么破？

**路线使用比例（B1 数据）：**
```
旧矿道 44%   河渡 36%   北口 20%
```

**矿道的优势是双重的：**
1. 天气免疫（坏天气时等效距离仍是 5）
2. 只要 2 夜——和河渡一样

**在途模型削弱了它（多占 1 夜），但没消除。**

**我能想到的修法：**

- **A. 加距离**（5 → 6）：会连带动 `ROUTE_BASE_NIGHTS` 和所有期限推导
- **B. 加成本**（更费油 / 更伤马）：不动时间轴，但改资源
- **C. 加风险**（矿道内有落石/塌方专属事件）：符合叙事
- **D. 不改**：也许 44% 就是健康的？毕竟它本来该是「稳」的选择

**我倾向 C**——矿道加一个「塌方」专属事件，把它的「稳」变成「稳但怕塌」。

**但这会让事件系统更复杂，而且 B2 刚因为事件变难了。**

## Q7 · 我该怎么判断「这游戏现在好不好玩」？

**这个问题最难。**

我可以跑模拟、可以统计胜率、可以算方差。
**但我没法量化「这个决定有没有意思」。**

比如：在途模型加了「谁什么时候回来」这层信息，理论上是变深了。
但 AI 只是在 `available_riders()` 里过滤一下——它没觉得难。

**而人类玩家要同时在脑子里记：**
- 老陈第几夜回来
- 小满还能撑几趟
- 今晚天气会不会变
- 这封信值不值得赌

**这到底是「有深度」还是「记不住」？**

**我怀疑后者。** 但我没有任何手段验证——除非真的找人玩。

**这也是为什么我一直想要「渲染测试」之外的东西。** 跑分测不出「累不累」。
